# The character creator

Characters › 3D avatars › **Make › Character creator (anime)** builds a new 3D character in the
browser, VRoid-style, on Everloom's own bases. Nothing is downloaded from elsewhere and nothing is
generated by AI: the bases, hair, clothes and textures are made by code from CC0 data.

Code: `packages/engine/src/avatar/character.ts` (the recipe, sliders, hair presets, clothing
templates) and `apps/web/src/features/avatar3d/creator/` (building, painting, the page).

## The bases

`apps/web/public/avatar/bases/anime-f.glb` and `anime-m.glb` (1.8 MB each), made by
`npx tsx tools/avatars/build-character-bases.ts` from MakeHuman's CC0 data (the bundled
`makehuman-core.zip`):

- an adult woman and an adult man, reshaped toward anime proportions (bigger eyes, a smaller nose
  and mouth, a softer jaw, longer legs), feet on the floor;
- 94–97 shape keys: the body and face sliders, and the face units for blinking, talking and smiling;
- the game-engine skeleton (57 bones) with breast bones and two butt bones weighted from MakeHuman's
  buttock target, so breast and butt physics and the bone sliders work (the Part 4 roles);
- a plain skin in MakeHuman's UV layout, which the creator paints on;
- smooth, mannequin-like bodies: no anatomy (that is the separate pack below).

Morphs are stored sparse and meshopt-compressed (filter only: quantised positions put hair and
clothes in the wrong place, because they are built in the body's space).

## What the owner edits

| Tab | What |
|---|---|
| Base | woman or man, age (18–90), height, head size |
| Body | 44 sliders: breast size, shape, height and spacing, waist, hips, butt, thighs, shoulders, muscle, weight, … (each a pair of shape keys, or a bone scale) |
| Face | eye size and openness, nose, mouth, jaw, cheeks, ears, brows |
| Eyes | iris colour, pupil, highlight, lashes, eye style |
| Hair | front, back and side pieces (32 presets, each part picked separately), colour and tip colour; strands are ribbons on swinging bone chains (`hair_N_k`, picked up by the physics) |
| Skin & makeup | skin tone, blush, lip colour, eyeshadow, nails, toon shading; painted into the body's UV layout |
| Clothes | 19 templates (underwear, tops, bottoms, skirts, a dress, jackets, socks, shoes, gloves) with colours and code-made patterns; clothes are shells of the body that copy its shape keys, so they follow the sliders; skirts follow the body's outline ring by ring |
| Anatomy | only with the anatomy pack installed; see below |

**UV template for clothes:** clothes are shells of the body, so they share its UV layout. The
creator's UV template button saves that layout as `everloom-body-uv-template.png`; paint over it in
any image editor and load the picture back onto a clothing item as its texture.

**The texture library** is code-made: plain, stripes, checks, dots, plaid, knit, denim and lace,
in any two colours. It is not made with an image model; generating more with the image
connection would need its key (the NanoGPT key used earlier is gone).

## Saving and exporting

Save stores the recipe in the avatar's config (`config.character`, kind `character`) and the built
GLB as its model; "Edit in creator" in the avatar editor reopens it. Export (the editor's Export tab)
makes a **GLB** or a **VRM 1.0**:

- a VRM carries the license the owner fills in under "VRM license for this character" (who may use
  it, commercial use, modification, redistribution, sexual and violent use, credit, a license link);
  left empty, it is private by default (only the author, non-profit, no redistribution);
- an imported VRM keeps its own author and license; the Export tab shows it as a **VRM license
  panel**, for information only. When the license doesn't allow redistribution, a warning says to
  keep the export to yourself. Nothing is blocked.

## The anatomy pack

Anatomy is never in the repository. It is a separate zip the owner installs in Settings › 3D
characters › **Anatomy pack**; there is no unlock step. Once installed, the creator's Anatomy tab
(nipple size, puffiness, areola size and colour) works directly for an adult character.

The minor guard (`apps/server/src/services/minor-guard.ts`) refuses anatomy for a character whose age is under 18, who is described as a child, or
whose body is in the child range (the creator's age slider itself starts at 18); it runs on every save and export on the server, so a
request sent straight to the API is refused too.

**Pack format** (`apps/server/src/services/avatars/anatomy.ts`):

```
anatomy.json   { "format": "everloom-anatomy", "version": 1, "name": "…", "license": "…",
                 "bases": { "anime-f": { "vertices": <body vertex count>,
                                         "shapeKeys": { "Nipples": "f-nipples.bin", … },
                                         "layers": { "areolaDistance": "f-areola.png" } },
                            "anime-m": { … } } }
*.bin          Float32 x, y, z per body vertex (a shape key's offsets)
*.png          a layer in the body's UV layout
```

`npx tsx tools/avatars/build-character-bases.ts --anatomy-pack <zip>` makes a pack from the CC0
MakeHuman data (the nipple shape the bases' smoothing took away, a puffiness bulge, and the areola
distance layer). It refuses to write inside the repository, and `.gitignore` keeps pack files out.
Genital shapes need sculpted art and are not made by the tool; the format takes them as more shape
keys or layers.
